## ★ 危ない部分に触らずに作れることが分かった（2026-09-19 追記）

当初この文書には「`bgm.js` のギャラリー対応が本丸。中〜大」と書いた。
**調べ直したら、その必要がなかった。**

12曲は**すべて `bgm.js` の `TRACKS` に載っている名前**で、
`BGM.play(name)` をそのまま呼べる。しかも12曲とも `NO_RESUME` に入っているので、
**呼ぶたびに頭から鳴る。** ギャラリーとして欲しい動きがそのまま出る。

```js
var NO_RESUME = { battle: 1, battle2: 1, battle_dungeon: 1,
                  arena1: 1, arena2: 1, arena3: 1, arena4: 1, arena5: 1,
                  midboss: 1, king1: 1, king2: 1, king3: 1, king4: 1,
                  boss: 1, lastboss: 1, ending: 1, gameover: 1 };
```

**つまり v1 は `bgm.js` の再生まわりを一切書き換えずに作れる。**

足すとしても「いま何の曲が何秒か」を読むだけの取得口で、
**鳴り方を変えない追加**に留められる。

これが効くのは、`bgm.js` が実機で何度も焼かれている場所だから。
「タップのたびに戦闘曲が鳴り直す」も、まだ直っていない
「iPhone で効果音が途切れる」も、この周辺で起きている。
**今回はそこを踏まずに済む。**

## すでにあるもの

### 1. クリア回数は記録されている

`party/js/pmain.js` が冒険の完結時にこれをやっている。

```js
rc.clears = (rc.clears || 0) + 1;
saveRec(rc);
```

保存先は `localStorage` の `wq2_records_v1`。
「称号・記録」の画面にも「冒険 完結 ○回」として出ている。**新しく数える必要はない。**

### 2. 「条件を満たしたら項目が出る」仕組みも、もうある

「挑戦の塔」がまさにそれ。`pmain.js` の1行。

```js
$("pbtn-tower").style.display = (rc.clears > 0) ? "" : "none";
```

同じ形で書ける。

```js
$("pbtn-ost").style.display = ((rc.clears || 0) >= 5) ? "" : "none";
```

### 3. 曲はすでにアプリに入っている

**配信ビルドに 17曲・45MB が同梱済み。** ギャラリーを足しても
**アプリの大きさはほぼ増えない。** これは大きい。

### 4. 重ねて出す画面の作り方も決まっている

`wq2-store-ovl` というクラスで、「称号・記録」「単語帳」「学年をえらぶ」が
すべて同じ作りになっている。真似すればよい。

## 作るもの

### A. 解放の判定とボタン ── 小

上に書いた1行と、`party/index.html` にボタンを1つ。
5回目のクリア時に「サウンドトラックが解放されました」と出す処理も足す
（1回目のクリアで何か出す処理が既にあるので、その隣に置ける）。

### B. 曲名と並び ── **これは私の仕事ではない**

中の名前がそのままでは出せない。

```
king2  battle_dungeon  midboss  arena3  lastboss  …
```

**日本語の曲名を付ける必要がある。** 21曲ぶん。
一覧と長さは下の表に出してある。案は出せるが、**決めるのは本人。**
ゲームの曲名は作者の言葉であって、こちらが勝手に付けるものではない。

### C. プレイヤーのギャラリー対応 ── **ここが本丸。中〜大**

`js/bgm.js` の先頭に、こう書いてある。

> One element on purpose. iOS Safari only lets a media element begin playing
> from a user gesture, and that permission sticks to the *element* —

**iOS は「最初のタップで解禁した要素」しか鳴らせない。**
ギャラリー用に2つ目の `<audio>` を作ると、**iPhone では無音になる。**

だから既存の要素を使い回すしかない。そのために `bgm.js` に足すもの：

- 曲を名前で鳴らす（ループするか / 1回で終わるか）
- 再生位置と長さを外から読めるようにする
- ギャラリーを閉じたら、ゲームの曲に戻す

**この作業の怖いところは、`bgm.js` が実機で何度も焼かれているファイルだという点。**
「タップのたびに戦闘曲が頭から鳴り直す」も、「iPhone で効果音が途切れる」も、
この周辺で起きている。**触るなら実機確認が要る。**

### D. 画面 ── 中

曲の一覧、いま鳴っている曲、再生位置のバー、停止と次へ。
`wq2-store-ovl` を真似れば形にはなる。

## 決めてほしいこと

### 1. ストーリーモードの4曲を入れるか

`tools/build_www.js` に、こう書いてある。

```js
// BGM used only by that story mode
var SKIP_BGM = ["field", "town", "dungeon", "battle_dungeon"];
```

ストーリーモードが制作中なので、**この4曲は配信ビルドに入っていない。**

| | |
|---|---|
| 入れる | 曲数が 17 → 21 に増える。**アプリが約16MB太る** |
| 入れない | いま入っている17曲だけ。**アプリの大きさは変わらない** |

> 入れると「聴けるのに、その場面が game に無い」ことになる。
> 先出しの楽しみとも取れるし、混乱の元とも取れる。
> **私は入れないほうに寄る。** ストーリーモードを出すときに足せばよい。

### 2. プレミアム加入者は即解放にするか

技術的にはどちらでもできる（`WQ2_STORE.isPremium()` がある）。

> **私は「しない」に寄る。** 5回クリアしたご褒美という筋と、
> お金を払ったご褒美という筋が混ざると、どちらの意味も薄くなる。
> ただしこれは商売の判断なので、本人が決めること。

### 3. 5回は妥当か

1回の冒険が11戦。**5回は相当な時間がかかる。**
到達する人がほとんどいない数字なら、作っても誰も見ない。

`rc.clears` は既に記録されているので、**いま何回クリアされているかは
あとから統計で見られる**（ただし手元に集まる仕組みは無い）。

> 3回か5回か。**迷うなら3回**にしておいて、簡単すぎたら次で上げるほうが安全。
> 逆は「前は見られたのに」になる。

**どちらも審査と実装の両方で重い。** まず画面を開いている間だけ鳴るもので

## 正直に言っておく弱点

### 音が小さい

配信する mp3 は `BGM_GAIN = 0.62` を焼き込んである
（読み上げを聞かせるため 0.73 から下げた）。

**そして iOS は `<audio>` の `volume` を受け付けない。**
`bgm.js` にもそう書いてある。つまり**ギャラリーで音量を上げることはできない。**

サウンドトラックとして聴くには、やや小さい音で鳴る。
端末の音量を上げてもらうしかない。

> 全音量の別ファイルを同梱すれば解決するが、**+45MB。** 割に合わない。
>
> Web Audio に繋げば音量は取れるが、`bgm.js` には
> 「createMediaElementSource に繋いだ要素は src を差し替えても鳴り始めない
> ことがある（WebKitの既知のふるまい）」として**一度撤去した記録がある。**
> ギャラリー専用なら曲の入れ替え頻度が低いので通るかもしれないが、
> **v1 では踏まない。** 実際に「音が小さい」と言われてから考える。

### 解放は端末ごと。消える

`wq2_records_v1` は localStorage。**アプリを入れ直すと 0 に戻る。**
クラウド保存の仕組みは無い。

5回クリアした人がそれを失うのは、他の記録（単語帳・称号）も同じなので
この機能だけの問題ではない。**が、「解放」という言葉を使う以上、
失われたときの落胆は大きい。** 頭には置いておく。

## 順番

**① iPhone 12 の音切れの原因を先に掴む。**

いま `js/audio.js` に計測を仕込んであり、実機のデータ待ちの状態。
効果音が半分の確率で途切れる原因が分かっていない。

**その原因が `bgm.js` 側にもある可能性がある。** 分からないまま `bgm.js` を
触ると、直したのか壊したのか判別できなくなる。**先に切り分ける。**

② 曲名を決める（本人）
③ 解放判定とボタン（小）
④ 画面（中）
⑤ `bgm.js` のギャラリー対応（中〜大）＋ **iPhone 実機確認**

⑤だけは実機が要る。いま触れる iPhone は娘さんの12だけ。
