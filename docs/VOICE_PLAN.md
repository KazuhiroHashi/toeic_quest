# リスニング音声（英単語の読み上げ）実装計画

問題が出た瞬間に単語を音声で読み上げる。設定でオフにできる。
2026-08-22 時点。**生成はMacのローカルで行う。**Higgsfield（seed_audio）は使わない。

---

## 決まっていること

| | |
|---|---|
| 端末側の音声合成 | **使わない。**こちらで作った音声ファイルを同梱して再生するだけ |
| 生成 | **Macのローカルで Kokoro-82M（Apache-2.0）**。1語ずつ生成する。費用ゼロ |
| 声 | 単語ごとに男性か女性のどちらか1つ。**同じ単語はいつも同じ声** |
| 女性の声 | `af_kore`（米）。語尾リフト中央値 -4.7半音、最悪 -0.7半音、上がった語 0/12 |
| 男性の声 | `bm_george`（英）。中央値 -8.5半音、最悪 -0.6半音、上がった語 0/12 |
| 対象 | 4,883語（TOEIC 1,907 ＋ 中高 4,016 − 重複 1,040） |
| 内訳 | 女性 2,483語（50.8%）／ 男性 2,400語（49.2%） |
| 形式 | mp3 / モノラル / 24kHz / 32kbps |
| 容量 | 1語あたり平均 3.5KB → **全体で約17MB**（ビルドは 64MB → 81MB） |
| 生成時間 | 実測 1語0.35秒 → **4,883語で約30分** |

**声を単語ごとに割り振るので、音声データは2倍になりません。**
割り当ては単語名のハッシュ（FNV-1a）で決めているため、作り直しても同じ結果になります。

## 生成の手順（検証済み）

### 1. 割り当てを作る

```bash
node tools/build_voice_list.js
# → build/voice_plan.json   単語 → { 声, ファイル名 }
```

`build/voice_batches.json` も出るが、**まとめ生成はしないので使わない。**

### 2. 準備（初回だけ）

```bash
pip install kokoro-onnx soundfile
curl -L -o build/kokoro-v1.0.onnx \
  https://github.com/thewh1teagle/kokoro-onnx/releases/download/model-files-v1.0/kokoro-v1.0.onnx
curl -L -o build/voices-v1.0.bin \
  https://github.com/thewh1teagle/kokoro-onnx/releases/download/model-files-v1.0/voices-v1.0.bin
```

モデルは合計354MB。`build/` は .gitignore 済みなのでコミットされない。
語が飛ぶ・音が出ないときは `brew install espeak-ng`。mp3変換に ffmpeg を使う。

### 3. 生成する

```bash
python3 tools/gen_voice_local.py --limit 30   # まず30語で確かめる
python3 tools/gen_voice_local.py              # 4,883語（約30分）
```

`assets/voice/<単語>.mp3` が直接できる。**切り分けは不要。**
途中で止めても、次に走らせると残りだけ作る。声を変えるときは
`--female af_bella --male am_fenrir` のように指定する。

## なぜ Higgsfield（seed_audio）をやめたか

**40語まとめて読ませると、語尾が疑問形に上がる。**リスト読みの抑揚が付くため。

`negotiate` は語末が単語の本体より **+3.3半音** 高く終わっていた。
文面は総当たりで試した（大文字化・三点リーダ・語順の入れ替え・2回読ませ）が、
**どれも効かなかった。**単語のせいではなく位置のせいで、`negotiate` を最後に動かすと平らになり、
かわりにそこへ来た `watch` が跳ね上がった。1語だけで生成すればきれいに下がる。

つまり直し方は「1語ずつ生成する」しかない。seed_audio でそれをやると
4,883回 × 0.4クレジット = **約1,950クレジット**かかる。ローカルなら無料で30分。

**macOS の `say` は使えない。**Apple のライセンス契約が、システム音声で作った音声の
商用の文脈での記録・公開・再配布を禁じている（個人的・非商用の制作にかぎる）。
このアプリはストアに出して広告も入るので条件を満たさない。Kokoro は Apache-2.0 なので問題ない。

### 声の選び方（測定済み）

22人の声に12語ずつ読ませ、**語尾リフト**（語末0.22秒の平均F0が、それ以前より何半音高いか）を測った。
＋が大きいほど疑問形に聞こえる。＋1.5半音超を「上がった」と数えた。

1. `af_kore`（女・米）中央値 -4.7 ／ 最悪 -0.7 ／ 0/12 ／ ピーク -2.5dBFS → **採用**
2. `bm_george`（男・英）中央値 -8.5 ／ 最悪 -0.6 ／ 0/12 ／ ピーク -4.8dBFS → **採用**
3. `af_bella`（女・米）中央値 -3.6 ／ 最悪 -0.9 ／ 0/12 ／ ピーク -4.9dBFS
4. `bf_lily`（女・英）中央値 -5.3 ／ 最悪 -0.3 ／ 0/12 ／ ピーク -1.2dBFS
5. `am_fenrir`（男・米）中央値 -6.1 ／ 最悪 -2.0 ／ 0/12 ／ ピーク 0.0dBFS（要音量下げ）

参考：seed_audio Emily は 中央値 -5.0 ／ **最悪 +3.3** ／ 2/6。
`am_onyx` と `bm_lewis` は明確に上がるので使わない。

実データ43語（熟語含む）で試し、上がったのは冠詞の `a` と `as soon as possible` の2件だけだった。
熟語は1ファイルに収まる（`as soon as possible` で1.39秒）。

## まだやっていないこと

### ① 声の最終確認（承認待ち）

`af_kore` と `bm_george` で進めてよいか。聞き比べは
`docs/voice_samples/` と、比較ページで確認できる。別の声にする場合は
`tools/gen_voice_local.py` の `FEMALE` / `MALE` を変えるだけ。

### ② 再生の実装

- `assets/voice/<単語>.mp3` を、問題が出た瞬間に再生
- **BGMは止めない。**音量を下げて重ねる（BGMを切ると戦闘の緊張が切れる）
- タイトルに **「英語の音声」のオン／オフ**を追加。`localStorage` に保存
- iPhone対策：`js/bgm.js` と同じく、**最初のタップで解禁した1つの要素を使い回す**。
  声用に専用の要素を1つ持ち、`src` を差し替えて鳴らす。
  要素を単語ごとに作ると iOS では鳴りません（BGMで実際に踏んだ問題）
- 音声が無い単語（生成漏れ・熟語など）は**黙って飛ばす**。エラー音は出さない

### ③ ビルドへの組み込み

- `tools/build_www.js`：`assets/voice/` をそのままコピー（変換しない。すでに32kbps）
- `tools/build_inline_assets.js`：**プレビュー版には入れない。**
  17MB あるので 16MB のアーティファクト上限に収まりません

## 補足：なぜ端末の音声合成を使わないか

別のTOEIC学習アプリでの経験から、**端末側で合成した音声は品質が安定せず、
OSの更新で急に変わる**ため使わないと決めています。容量17MBを払ってでも、
こちらで作った同じ音声を全員に届けます。
