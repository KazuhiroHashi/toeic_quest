# リスニング音声（英単語の読み上げ）実装計画

問題が出た瞬間に単語を音声で読み上げる。設定でオフにできる。
2026-08-22 時点。**声の生成以外はすべて準備済み。**

---

## 決まっていること

| | |
|---|---|
| 端末側の音声合成 | **使わない。**こちらで作った音声ファイルを同梱して再生するだけ |
| 声 | 単語ごとに男性か女性のどちらか1つ。**同じ単語はいつも同じ声** |
| 男性の声 | seed_audio の既定（サンプル承認済み・2026-08-21） |
| 女性の声 | **Emily を推奨・承認待ち**（preset `6b3e3642-f7b7-4cb8-9688-51e233c4b92f`）。サンプル 2026-08-21 |
| 対象 | 4,883語（TOEIC 1,907 ＋ 中高 4,016 − 重複 1,040） |
| 内訳 | 女性 2,483語（50.8%）／ 男性 2,400語（49.2%） |
| 形式 | mp3 / モノラル / 24kHz / 32kbps |
| 容量 | 1語あたり平均 3.5KB → **全体で約17MB**（ビルドは 64MB → 81MB） |

**声を単語ごとに割り振るので、音声データは2倍になりません。**
割り当ては単語名のハッシュ（FNV-1a）で決めているため、作り直しても同じ結果になります。

## 生成の手順（検証済み）

1語ずつ生成すると 4,883 回になるので、**40語を1回にまとめて生成し、無音で切り分けます。**
8語で検証したところ、区切りが 1:1 で取れました。

### 1. 割り当てとバッチを作る

```bash
node tools/build_voice_list.js
# → build/voice_plan.json   単語 → { 声, ファイル名 }
# → build/voice_batches.json  123バッチ（1回40語）
```

貼り付ける文面を見るには `--show 3`。単語は `.` と空行で区切ってあります。

### 2. 生成する（Higgsfield / seed_audio）

```
mcp__Higgsfield__generate_audio  model: "seed_audio", prompt: <バッチのprompt>
```

- 1回あたり **0.4クレジット**。123回で **約50クレジット**
- 40語で 40〜50秒の音声になります

### 3. 切り分ける

```bash
node tools/split_voice.js <落としたwav> --batch f000
# → assets/voice/<単語>.mp3
```

**区切りの数が語数と合わない場合、このツールは何も書き出さずに失敗します。**
1語ずれると、以降すべての単語に別の単語の音声が付いてしまうためです。
その場合は `NOISE` / `MINSIL` を調整するか、そのバッチを分割して作り直します。

## まだやっていないこと

### ① 女性の声を決める（サンプル作成済み・承認待ち）

seed_audio の preset ボイスから女性5人を選び、**全員に同じ6語を読ませました**。
費用は 2.0 クレジット。音声は `docs/voice_samples/*.wav`（wav / 24kHz / mono）。

```
negotiate.  discrepancy.  unfortunately.  watch.  thorough.  available.
```

**この5本は seed_audio の既定パラメータのままです。**
実際に調整できるのは `speech_rate` / `loudness_rate` / `pitch_rate` の3つで、
`mood` や `expression_intensity` は seed_audio には存在しません（当初の想定は誤り）。

#### 測った結果

声の好みとは別に、**切り分けが通るかどうかで先に足切りできます。**
`split_voice.js` は「-38dB 以下が 0.20秒以上」を語の区切りとみなすので、
語間の無音がこれを下回る声は 123バッチのどこかで必ず失敗します。

1. **Emily**（`6b3e3642-f7b7-4cb8-9688-51e233c4b92f`）語間 0.39秒／単語内 0.09秒／ピーク -5.9dBFS／発声 4.43秒 → **推奨**
2. Ainsley（`731b4ffe-e95e-59f4-8c00-81608936091f`）語間 0.29秒／0.08秒／ピーク -0.8dBFS／5.21秒 → 音量が天井
3. Naomi（`caeba733-3c17-43db-863e-69c7025512cd`）語間 0.33秒／0.14秒／ピーク -12.6dBFS／4.89秒 → 音量が小さい
4. Maya（`b0f766b7-8703-4bd1-b973-f857c36837b6`）語間 0.265秒／0.10秒／ピーク -1.0dBFS／4.95秒 → 音量が天井
5. Nora（`d081b915-6623-4a44-bacf-80d0f1c90a03`）語間 **0.20秒**／単語内 0.175秒／ピーク -4.1dBFS／5.62秒 → **採用不可**

Emily を推す理由は3つ。**語間 0.39秒はしきい値の倍近くあり、切り分けの余裕が唯一大きい。**
ピーク -5.9dBFS は歪む心配も埋もれる心配もない。読みが一番速いのでファイルも小さくなります。

Nora はしきい値ちょうどで、しかも単語内の無音が 0.175秒あります。差が 0.025秒しかなく、区別できません。
Maya と Ainsley を選ぶ場合は `loudness_rate: -10` 前後で作り直すのが前提です。

#### 決まったら

`build_voice_list.js` は変更不要です。生成のときに声を指定するだけ。

```
mcp__Higgsfield__generate_audio
  model: "seed_audio"
  prompt: <バッチのprompt>
  voice_type: "preset"
  voice_id: "6b3e3642-f7b7-4cb8-9688-51e233c4b92f"   // Emily（女性バッチ f000〜 のみ）
  format: "wav", sample_rate: 24000
```

男性バッチ（m000〜）は既定のまま、`voice_type` / `voice_id` を付けずに生成します。

### ② 再生の実装

- `assets/voice/<単語>.mp3` を、問題が出た瞬間に再生
- **BGMは止めない。**音量を下げて重ねる（BGMを切ると戦闘の緊張が切れる）
- タイトルに **「英語の音声」のオン／オフ**を追加。`localStorage` に保存
- iPhone対策：`js/bgm.js` と同じく、**最初のタップで解禁した1つの要素を使い回す**。
  声用に専用の要素を1つ持ち、`src` を差し替えて鳴らす。
  要素を単語ごとに作ると iOS では鳴りません（BGMで実際に踏んだ問題）
- 音声が無い単語（生成漏れ・熟語など）は**黙って飛ばす**。エラー音は出さない

### ③ ビルドへの組み込み

- `tools/build_www.js`：`assets/voice/` をそのままコピー（変換しない。すでに32kbps）
- `tools/build_inline_assets.js`：**プレビュー版には入れない。**
  17MB あるので 16MB のアーティファクト上限に収まりません

## 補足：なぜ端末の音声合成を使わないか

別のTOEIC学習アプリでの経験から、**端末側で合成した音声は品質が安定せず、
OSの更新で急に変わる**ため使わないと決めています。容量17MBを払ってでも、
こちらで作った同じ音声を全員に届けます。
