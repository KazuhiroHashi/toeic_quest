# WORDRIA 集客 手順書

2026-09-25 夜に作成。**この夜のあいだ、外には何も出していない**（SNS・ストア・サイト・Google Play のどれにも触っていない）。
朝に読んで、各ステップの「go」を出すか、自分で実行するための手順書。

## 0. 最初に：見通しを正直に

- 一晩ではダウンロードは増えない。**増え始めるのは、下の A〜C を実行した日から**
- 数字の約束はしない。App Store の新規アプリは、SNS から来る人がストア検索の順位を押し上げ、そこから検索経由の人が来る、という順で伸びる。**最初の1〜2週間の目的は「どの経路が効くか」を見つけること**
- ストアのキーワード欄（96字）、説明文、スクリーンショットはもう整っている。評価依頼の仕組みもある（ただし出る場面が少ない → E）。**いちばん足りないのは「外から見つけてもらう入口」**

## 1. 守ること（迷惑・個人情報）

どのステップにも共通。迷ったらやらない。

| 出さない・しないこと | 理由 |
|---|---|
| 本名・顔・住まい・勤め先・**家族の話** | 個人情報。`pr-strategy.md` の「娘のために作った」案も**使わない** |
| 画面収録に通知・時計・端末名が映る | 通知にはメッセージや名前が出る。撮る前に**おやすみモード** |
| 同じ文面の連投、無関係なハッシュタグ、トレンド便乗 | スパム扱いされ、アカウントの評価も下がる |
| 他人の投稿へのリプライ・DM での宣伝 | 迷惑行為 |
| レビューやフォローに見返りをつける、相互レビュー | Apple 1.1.7 / 3.2.2 違反。アプリごと消える |
| 掲示板（5ch など）への書き込み | 迷惑行為として拡散されるリスクが大きい |
| 速度ボーナスなど、仕組みの細部を文面に書く | 「遊べば分かる」の方針（`STORE_LISTING.md` 268行目） |

発信者名は **Bridge AI**。X のアカウントが本名のものしか無いなら、先に Bridge AI 名義のアカウントを作るかを決める（決めるまで B は保留でよい）。

## 2. 朝の手順（合計 60〜90分）

| | やること | 所要 | 準備してあるもの | 誰がやるか |
|---|---|---|---|---|
| **A** | 15秒の画面収録を撮る | 10分 | 撮り方（`growth/x_posts.md` 末尾） | あなた |
| **B** | X に投稿1を出し、投稿2を返信でつなぐ | 10分 | 文面（`growth/x_posts.md`）。文字数は確認済み | あなた（あなたのアカウント） |
| **C** | note に開発記を公開 | 30分 | 全文の下書き（`growth/note_draft.md`）と公開前チェック | あなた（あなたのアカウント） |
| **D** | 紹介ページに App Store バナーと説明文を足す | 5分 | 差分（下の §3） | 「**D go**」で私が作業ブランチまで。公開（main へのマージ）はあなた |
| **E** | 次のアプリ更新に、評価依頼の改善と広告のバグ修正を入れる | 準備 10分、審査数日 | 差分（下の §4） | 「**E go**」で私がゲームブランチまで。ビルドと審査提出はあなた |

**A → B → C の順が大事。** C（note）は B（X）でシェアして初めて読まれる。
D と E は、A〜C と並行して「go」だけ出してもらえれば進められる。

### B の出す時間

- **今日の 21:00 前後**に投稿1＋投稿2（返信で続ける）
- 翌日以降、1日1本まで：投稿3（開発の学び）、改名の話、バグの話（`growth/x_posts.md`）
- note を公開したら、その日の夜に「開発記を書きました」とリンク付きで1本

### C の注意

`growth/note_draft.md` の末尾にある「公開前の確認」6項目を必ず見る。
**実体験かどうか私が確かめられない文**に印をつけてある。事実でなければ削る。

## 3. D：紹介ページの差分（bridge-ai-tokyo リポジトリ）

今夜はこのリポジトリへのアクセス許可が下りなかったので、**変更は一切していない**。
公開中の `https://bridge-ai-tokyo.com/wordria/` を読んで差分を作った。

### 3-1. App Store のスマートバナー（効果が一番大きい）

`wordria/index.html` の `<head>` 内、`<meta name="theme-color" …>` の下に1行足す。

```html
<!-- iPhone の Safari で開いたとき、画面上部に App Store の「入手」バナーを出す -->
<meta name="apple-itunes-app" content="app-id=6805523364">
```

X や note のリンクから来た iPhone の人に、ページの上で直接「入手」を押してもらえる。

### 3-2. 検索結果に出る説明文

いまは `content="単語帳を開くより、冒険しよう。"` だけで、Google で「英単語 ゲーム」などと調べた人に何のページか伝わらない。
`description` と `og:description` の2か所を差し替える。

```html
<meta name="description" content="英単語の意味を4択で答えて戦う、無料のコマンドバトル英単語RPG。中学英語から大学受験・TOEIC®頻出語まで学年別に出題。全単語に読み上げ音声つき。">
<meta property="og:description" content="英単語の意味を4択で答えて戦う、無料のコマンドバトル英単語RPG。中学英語から大学受験・TOEIC®頻出語まで学年別に出題。全単語に読み上げ音声つき。">
```

キャッチコピー「単語帳を開くより、冒険しよう。」はページ本文にそのまま残る。消えるのは検索結果の説明欄だけ。

### 3-3. 確認

main に入れて GitHub Pages に反映されたら、iPhone の Safari で `https://bridge-ai-tokyo.com/wordria/` を開き、上にバナーが出るか見る。
（Chrome やアプリ内ブラウザでは出ない。Safari だけ）

## 4. E：次のアプリ更新に入れるもの（toeic_quest）

| | 内容 | 状態 |
|---|---|---|
| E-1 | **広告が20本で止まるバグ**の修正（`93083fd`） | 作業ブランチにコミット済み。ゲームブランチには未反映 |
| E-2 | **評価依頼を5戦目（古竜）の勝利後にも出す** | 差分 `growth/review_prompt.patch`。構文チェックと `git apply --check` は通過。**まだ当てていない** |
| E-3 | タイトルの「評価する」ボタン（iOS）で、App Store のレビュー画面を直接開く | E-2 と同じ差分に入っている |

### E-2 の理由

いまは**闘技場を最後まで制覇した人にしか評価をお願いしていない**（`prate.js` の `MIN_CLEARS = 1` と、呼び出しがエンディング後だけ）。
11戦を勝ち切る人はごく一部なので、レビューが集まらない。
5戦目の古竜は1周の前半の山場で、勝った直後は気持ちが乗っている。

- 上限（一生で3回・前回から90日あける）は制覇時と**共有**する。聞きすぎにはならない
- 評価シートのあと、6戦目の開始カード（Ａボタン）を挟んでから広告が出る。**評価シートと広告は続かない**
- 見返りは一切つけていない（Apple 5.6.1 のレビューゲーティングに当たらない）

### E-3 の理由

`prate.js` のコメントに「App Store の ID が採番されたら差し替える」とあり、ID `6805523364` が決まったのに未対応だった。
いまは OS の評価シートで代用していて、OS の回数上限に当たると**押しても何も出ない**。

### 「E go」で私がやること

1. 作業ブランチに `growth/review_prompt.patch` を当て、`node tests/check.js` を通してコミット
2. ゲームブランチ `claude/toeic-quest-game-8zva6k` に `93083fd` と上のコミットを cherry-pick して push
   （**ゲームブランチへの push はこの「go」を許可とみなす**）
3. `version` の番号は上げない（あなたがビルドするときに上げる）

### あなたがやること（E go のあと）

1. ビルド → **実機で確認**：闘技場で5戦目に勝つと評価シートが出るか／タイトルの「評価する」で App Store のレビュー画面が開くか
2. App Store に提出（審査）。Google Play も同じビルドで
