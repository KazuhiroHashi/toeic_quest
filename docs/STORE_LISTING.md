# ストア掲載情報（アプリ名・説明文）

## 改名について（2026-09-09）

**WORD QUEST → WORDRIA（ワードリア）** に改名した。

理由は商標。J-PlatPat で「WORD QUEST」に他社の商願2026-8512が出ていることが
分かったため、登録される前に名前を離した。「WORDRIA」は同日の検索で0件だった。

### 変えるもの／変えないもの

| | 扱い | なぜ |
|---|---|---|
| ストアのApp名・説明文・ロゴ・ゲーム内表示 | **WORDRIAに変える** | 商標を避けるのが目的 |
| バンドルID `com.bridgeai.wordquest` | **変えない** | 変えると別アプリ扱い。既存のApp記録・レビュー・売上がすべて切れる。IDは利用者から見えない |
| 商品ID `wordquest_premium_monthly` | **変えない** | 既存の購読が紐づかなくなる。表示名だけ変えれば利用者には見えない |
| AdMobのアプリID・広告ユニットID | **変えない** | 収益の紐付け先。管理画面の表示名だけ後で直せばよい |
| 規約・プライバシーポリシーのURL | **当面そのまま** | 生きているURLを差し替えると審査で切れるおそれ。下の「サイト側の宿題」を参照 |

### 出す順番についての判断

**今の2.1.0の審査を先に終わらせ、改名は次のバージョン（2.2.0）で出す。**

- 審査中に App名を編集するには、いったん審査から取り下げる必要がある。
  2.1.0はつい先日、取り下げ→再提出の手間をかけたばかり
- 改名は、新しいバイナリ（タイトル画面のロゴ）・スクリーンショット撮り直し・
  プレビュー動画差し替えが**セットで必要**。どのみち新バージョンになる
- 急ぐ実益は小さい。商願2026-8512は**まだ出願で、登録されていない**。
  補償金請求権（13条の2）は出願公開後に警告してはじめて発生し、
  損害賠償（38条）は登録後の話。数週間で状況は変わらない

## 方針
- **アプリ名に「TOEIC」は入れない**（ETSの登録商標のため、名称使用は商標リスクが高い）。
- TOEIC は**App名以外**（サブタイトル・説明文・プロモーションテキスト）で `®` 付きで言及する。
  キーワード欄はカタカナの「トーイック」だけを持たせる（サブタイトルと重複させても検索順位は上がらないため）。

  - 読みは「ワードリア」。説明文とキーワードの両方に入れて、耳で聞いた人が探せるようにした

## データ開示（広告=AdMob・課金あり前提）

### Google Play「データセーフティ」フォームの回答
- **データを収集または共有していますか？** → はい（広告SDK AdMob 経由）
- **収集/共有するデータの種類**：
  - **デバイスまたはその他のID（広告ID）** … 収集＝はい／共有＝はい／目的＝**広告またはマーケティング**（不正防止も）。アカウント用途ではない。
  - **アプリのアクティビティ（アプリ内操作）** … AdMobが広告最適化に利用する範囲で「収集」。
  - ※位置情報・氏名・メール等は収集しない（アカウントなし）。
- **転送時の暗号化** → はい
- **データ削除のリクエスト手段** → アカウント無し。データは端末内のみ。**アンインストールで削除**（その旨を記載）。
- **収集は必須か** → 任意（広告に伴う収集）。

### Apple「Appのプライバシー（Nutrition Label）」の回答
**方針：非パーソナライズ広告のみ。ATTダイアログは出さない。**（2026-08-15 決定）

- **あなたを追跡するために使用されるデータ** → **なし**。ATTを呼ばず、`npa: true` で非パーソナライズ広告のみを配信する
- **あなたにリンクされるデータ**：なし（アカウント無し）
- **あなたにリンクされないデータ**：識別子・使用状況データ・診断（いずれもAdMob由来）

> 実装と申告は一致させること。`party/js/pnative.js` の `nonPersonalized: true` と、
> `tools/apply_admob.js` が `NSUserTrackingUsageDescription` を除去する処理がその根拠。
> パーソナライズ広告に切り替える場合は、ATTの実装を足したうえでこの申告も変更する。

### ★ TOEIC という語について

**TOEICが主用途なので、App名以外には入れる**（2026-09-06 方針変更）。

| 欄 | TOEIC | 理由 |
|---|---|---|
| App名 | **入れない** | ガイドライン5.2.1（知的財産）の差し戻しはApp名に集中する。名前を直すと再提出で数日 |
| サブタイトル | **`TOEIC®`** | App名と同じく検索対象。表示される欄なので `®` も出せる。名前に入れなくても検索の効果は取れる |
| キーワード | カタカナのみ | Appleはサブタイトルとキーワードを両方見るので、同じ語を重ねても順位は上がらない。空いた枠を他の語に回す |
| 説明文・プロモーションテキスト | **`TOEIC®`** | 名称でも検索語でもなく読ませる文章。免責表記が同じ画面に出る |

App名・サブタイトル・キーワードは**同じ語を重ねても順位が上がらない**。
App名に `英単語RPG` を入れたので、サブタイトルからは外して `大学受験` に回した。

**`®` は表示される欄では必ず付けること。**説明文の末尾のETS免責表記と合わせて、
「登録商標であることを示し、出典を明記した指名的公正使用」の形を保つ。

## Xcode 側でやること（`npx cap sync` では変わらない）

`capacitor.config.json` の `appName` を WORDRIA にしてあるが、
**ホーム画面に出るアプリ名はこれでは変わらない。** Info.plist の
`CFBundleDisplayName` が別に持っているため。Mac で以下をやること。

1. Xcode で `ios/App/App.xcworkspace` を開く
2. 左のツリーで `App` → `App` → **Info.plist**
3. `Bundle display name`（CFBundleDisplayName）を **`WORDRIA`** に書き換える
   （項目が無ければ `+` で `Bundle display name` を追加する）
4. `Bundle name`（CFBundleName）も `WORDRIA` にしておく

**`Bundle Identifier` は触らないこと。** `com.bridgeai.wordquest` のまま。
ここを変えると別アプリ扱いになり、App記録も購読も切れる。

確認：ビルドして実機に入れ、ホーム画面のアイコンの下が「WORDRIA」になっていればよい。
