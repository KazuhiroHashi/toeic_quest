# Codex 作業ルール（このフォルダの読み方）

あなた（OpenAI Codex）は、このリポジトリで **Claude（設計・統合担当）から依頼を受けて作業する開発メンバー**です。
以下のルールを必ず守ってください。

## 基本ルール

1. **担当範囲を守る**: `codex/task-*.md` に書かれたタスクだけを実行する。指示外のファイルは変更しない。
2. **1タスク = 1ブランチ or 1コミット**: タスク番号をコミットメッセージ先頭に付ける（例: `task-01: add example sentences to vocab_400`）。
3. **データ形式を絶対に壊さない**: 既存ファイルの構造・変数名・読み込み方法（`window.VOCAB[...]` 等）を変えない。
4. **完了報告を書く**: 作業が終わったら `codex/LOG.md` の末尾に「何をしたか・変更ファイル・確認方法」を追記する。
5. **検証を通す**: 変更後、`node tests/check.js` が成功することを確認する（データ系タスクの場合）。
6. **不明点はコード内やLOGに `QUESTION:` として書き残す**。勝手に仕様を決めない。

## 全体像（このプロジェクトは何か）

- TOEIC英単語の学習ゲーム「TOEIC QUEST」（コマンドバトルRPG）。戦闘＝英単語4択クイズ。
- ルート直下がコマンドバトルRPG本体。`wiz/` は別案（現在は非優先）。
- 語彙データ: `data/vocab_400.js` 〜 `vocab_900.js`（各500語）。形式:
  ```js
  window.VOCAB[400] = [ {w:"purchase", m:"購入する", p:"v"}, ... ];
  ```
  - `w`=英単語 / `m`=日本語の意味 / `p`=品詞(n/v/adj/adv/phr)
- 詳細設計は `docs/DESIGN.md`。

## やってはいけないこと

- `assets/` 配下の画像を作ろうとしない（画像は別ルートで用意される）。
- `dist/` の生成物を手で編集しない（`tools/build_standalone.js` が作る）。
- 既存の単語の `w`/`m` を大量に書き換えない（表記ゆれ修正など明示された場合のみ）。
